# はじめに

Neovim を使っている大半の方は、プラグインを使って理想の環境を作っていると思います。便利なプラグインはたくさんありますが、「痒いところに手が届かない」部分もどうしても出てくるのではないでしょうか。

私は完全に自分好みのエディタにしたかったので、**プラグインを探して組み合わせるのではなく、欲しい機能を AI に Lua でゼロから書いてもらう**というスタイルで Neovim の設定を育ててきました。今ではプラグインを一切使用せずに自分の理想のエディタが動いています。

本記事では、プラグインと比較したメリット・デメリットや実際に作った機能を紹介します。

# Neovim を使ったことがない方へ

Neovim は他のエディタと違って、画面に表示される内容や操作を Lua というプログラミング言語で自由に書き換えられます。VSCode などの拡張機能は、あらかじめ用意された範囲内でしかカスタマイズできませんが、Neovim は土台から自分で書き換えられるので、その範囲に縛られず自由に作り替えられます。この自由度の高さが、AI と組み合わせたときに理想のエディタへ近づけやすい理由です。

実際にどんな機能を作ったかもこの後紹介するので、「こんな機能も作れるんだ」と参考にしていただいて、実際に触ってみてもらえたら嬉しいです。

# AI 時代にエディタは必要か？

エディタについての記事を書きつつも、正直エディタを触る時間はほとんど無くなりました。とはいえ自分でコードを触ったり、読んだりしたい時もあります。
だからこそ、ターミナルで全ての作業が完結する分、より素早く作業を進められる、そんなメリットも Neovim（Vim）にはあると思います。

それでもやはりほとんどエディタを使う機会は無くなっているので、最近は AI との協業を意識した機能を作成することで、AI 時代でも役立つエディタにすることを目指しています。

# プラグインを使う場合と比較したメリット・デメリット

## メリット

メリットはいくつかあります。

- **中身が全部読める・すぐ直せる**: プラグインだとブラックボックスになりがちな挙動も、自分（と AI）が書いたコードです。気に入らない部分や不具合に気づいたら、issue を立てて修正を待つことなく、その場で直せます。
- **自分好みにできる**: 既製のプラグインでは妥協しがちな細かい挙動も、自分の好みに合わせて自由に調整できます。
- **機能同士を連携させやすい**: 別々の作者が作ったプラグイン同士だと連携が難しいこともありますが、全部自分で書いているので、内部の仕組みを共有したり、機能をまたいで動かしたりしやすいです。
- **完全に自分好みのエディタを作れて楽しい**: プラグインでは実現しきれない細部まで、思い描いた通りに作れるのは楽しいです。

## デメリット

もちろんいい面ばかりではありません。

- **保守も全部自分（と AI）の責任**: プラグインなら誰かが直してくれるバグも、全部自分で気づいて直す必要があります。
- **Neovim 本体のアップデートに自分で追従する必要がある**: API の変更や非推奨化があれば、自分で気づいて直すことになります。
- **枯れたプラグインほどの完成度にはなりにくい**: 長年使われてきたプラグインが踏んできたエッジケースを、自分で一つずつ踏んで直していくことになります。
- **こだわりだすとキリがない**: 自由に手を加えられる分こだわり出すと時間が無限に溶け、本質的な開発に支障が出かねません。

当たり前ではありますが、このように自作は自由度が高い分、保守や安定性は自分で引き受けることになります。プラグインの手軽さを取るか、自由度の高さを取るかはトレードオフにはなりますが、AI の発達のおかげで保守はかなり楽になりました。
また、既存のプラグインやその他ツールの挙動を参考にできるので、割と簡単に完成度の高い機能が作れるようにもなりました。（素晴らしいプラグインやツールを作ってくださった先人に感謝🙏）

なお、本体のアップデートへの追従はプラグインでも事情は同じで、メンテナンスが止まったプラグインは Neovim 側の変更に追従されず、いずれ使えなくなります。自作は「自分で直す必要がある」代わりに「直せばすぐ使い続けられる」ので、ここは一方的なデメリットではないと思っています。

こだわりだすとキリがないという点に関しては、自分で制御するしかないですね・・

## Git 操作画面

ブランチ切り替え、コミット、ステージング/アンステージ、Stash、Worktree の追加削除、コンフリクトの解消、GitHub の PR や CI ステータス確認まで、Neovim の中だけで完結する Git 操作画面です。`lazygit` や `gh-dash` の挙動を参考にしながら作っています。
<!-- ここに実際のエディタのスクリーンショットを貼る -->

## Docker 操作画面

コンテナ・イメージ・ボリューム・ネットワークの一覧確認や、起動・停止・削除、コンテナ内シェルの起動までできる Docker 操作画面です。`lazydocker` の挙動を参考にしています。

Git 操作画面と画面のレイアウトやタブ切り替え、コマンドログといった UI の骨格を共通の仕組みとして使い回しているので、見た目と操作感がそのまま揃っています。同じ UI を使った、使用中ポートを一覧できるパネルもあります。

## ファイラー

場合によって使い分けたいので、ファイルツリー表示と `yazi` のようなカラム表示とを切り替えれるようにしています。

## あいまい検索・置換

ファイル内容やファイル名をあいまい検索できる機能です。VSCode の検索パネルのように、置換や include / exclude によるファイルの絞り込みにも対応しています。

## ブラウザでのプレビュー

編集中の Markdown や HTML をブラウザでプレビューできる機能です。直接ブラウザで開くのと違って、保存すると自動で反映されるので手動でリロードする必要がありません。AI にコードを書いてもらったときも、すぐに結果を確認できて便利です。

## 差分レビューをブラウザで AI と一緒に

Git 操作画面でも delta のような差分表示を用意しているので、差分をターミナルでサッと見たい時はこちらを使用しています。

## コードのメモを AI と共有する仕組み

ファイルの特定の行にメモを残せる機能です。ブラウザからも AI からも同じメモを参照・追記できるので、AI がメモを残して人間（もしくは他の AI）が読んだり、逆に人間が残したメモを AI が参照したりできます。

## Neovim の情報を AI に渡す仕組み

Neovim が内部に持っている情報（LSP の定義・参照・シンボル・ホバー、診断、開いているバッファなど）を、ローカルの HTTP API 経由で AI から読めるようにする機能です。grep と違って LSP はスコープを解決してくれるので、同じ名前のシンボルや import のエイリアスを AI が取り違えることがありません。問い合わせている間もエディタの操作は止まらないようになっています。

## Herdr との連携

最近の開発では [Herdr](https://github.com/herdrdev/herdr) をかなり重宝していて、

- Git 操作画面の worktree から Herdr のワークスペースを作成する
- 別パネルのエージェントを選んで、選択範囲を渡す
- 右ペインでブラウザを開く（後述）

といった Neovim と Herdr との連携機能も作成しています。

## terminal-browser との連携

Markdown / HTML のプレビューや差分レビューなど、ブラウザで開く機能を、GUI のブラウザではなくターミナル上で動く [terminal-browser](https://github.com/zenbu-labs/terminal-browser) で開けるようにしています。Herdr を使って右ペインで開くようにしている（すでに起動していれば同じブラウザで開きます）ので、ターミナルから離れずにプレビューまで確認できます。

この機能があるので、リッチな UI で確認したいようなものはターミナル上で用意するのではなく、ブラウザで見れるようにしています。

# その他の機能

細かいものも含めて、他の機能の一部を挙げておきます。

## エディタ / UI

- 開いているファイルをタブのように並べて切り替えられる表示（`bufferline.nvim`のような機能）
- 各ウィンドウの上部に、開いているファイルのパスを常に表示（`barbecue.nvim`のような機能）
- 各ウィンドウにスクロールバーを表示（`nvim-scrollbar`のような機能）
- tree-sitter による構文ハイライトとコードの折りたたみ（`nvim-treesitter`のような機能）。パーサとハイライトクエリは upstream のものを使い、ビルドと Neovim への組み込み部分を自前で書いています
- `Ctrl-d` / `Ctrl-u` のスクロールをアニメーションさせる機能（`neoscroll.nvim`のような機能）
- カーソルがあるコードのブロック範囲を縦線でハイライトする表示（`hlchunk.nvim`のような機能）
- 括弧やクォートを入力すると自動で対になる方も補完してくれる機能（`nvim-autopairs`のような機能）
- 単語や選択範囲を括弧・クォートで囲んだり、外したりできる機能（`nvim-surround`のような機能）
- 画面外にスクロールした親スコープの行を上部に固定表示する機能（`nvim-treesitter-context`のような機能）
- 全角スペースを灰色背景で可視化する機能
- 開いたファイルの中身からインデント幅を自動検出して適用する機能（`vim-sleuth`のような機能）

## Git

- 編集中の行にその行の最終更新者や日時をインラインで表示する機能（`gitsigns.nvim`のような機能）
- 変更のある行をエディタの余白に表示する機能（`gitsigns.nvim`のような機能）
- 現在行や選択範囲の GitHub 上のパーマリンクを生成してコピーする機能（`gitlinker.nvim`のような機能）
- コンフリクトが起きたブロックを色分けして、現在側・入力側・両方などを選んで解消できる機能（`git-conflict.nvim`のような機能）

## LSP

- 各言語のサーバー設定と、ホバー表示・リネーム・コードアクション・フォーマット・診断へのジャンプといった基本機能（`nvim-lspconfig`のような機能）
- カーソル位置の定義元・参照元・型定義・実装をプレビューパネルで確認できる機能（`glance.nvim`のような機能）
- 関数の呼び元・呼び先を折りたたみ式の木でたどれる呼び出し階層（VSCode の Show Call Hierarchy のような機能）
- ファイル内の関数名や変数名（シンボル）をアウトライン表示し、あいまい検索して移動できる機能（`aerial.nvim`のような機能）
- 入力中に自動でメニューが出る補完機能（`nvim-cmp`や`blink.cmp`のような機能）
- 関数の引数ヒントを自動表示するシグネチャヘルプ（`lsp_signature.nvim`のような機能）
- 開いているファイル全体の診断をまとめて確認できる問題パネル（`trouble.nvim`のような機能）
- カーソル下のシンボルと同じものをファイル内でハイライトし、読み取りと書き込みで色を分ける機能（`vim-illuminate`のような機能）

## ターミナル

- リポジトリのルートですぐに開けるターミナル（`toggleterm.nvim`のような機能）
- ターミナルのバッファをタブや一覧から隠し、キー一つでエディタとの行き来ができるようにする機能（`toggleterm.nvim`のような機能）

## その他

- `.http` / `.rest` ファイルに書いた HTTP リクエストを実行し、結果を確認できる機能（`rest.nvim`のような機能）
- 選択範囲をファイルパス・行番号付きのコードブロックとしてコピーする機能
- パスの断片を入力するとファイルやフォルダ名を補完してくれる機能（`cmp-path`のような機能）
- バッファの内容を丸ごとコピーする機能
- 本文をあいまい検索で引ける個人用のメモ帳
- メモや HTML の一覧をブラウザで読める画面（Markdown はコードハイライトと mermaid つきで表示）
- TODO や FIXME などのコメントタグをプロジェクト全体から検索して一覧表示する機能（`todo-comments.nvim`のような機能）
- キーバインドを一覧化してあいまい検索できるチートシート（`which-key.nvim`のような機能）

# さいごに

「プラグインを探して組み合わせる」のではなく「欲しい機能を AI に一つずつ書いてもらう」というスタイルで、ここまで Neovim を育ててきました。保守も安定性も自分で背負う分、理想の形に妥協せず近づけられるのが、このやり方の一番の魅力だと感じています。

今回紹介した機能もあくまで現時点のものです。気になる挙動を見つけるたびに、これからも AI と一緒に Neovim を育てていくつもりです。まだ触ったことがない方も、これを機に触ってみてもらえたら嬉しいです。
