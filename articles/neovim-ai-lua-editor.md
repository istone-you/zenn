# はじめに

Neovim を使っていると、誰しも一度は「プラグインを入れて理想の環境を作る」というところに行き着くと思います。便利なプラグインはたくさんありますが、複数を組み合わせると設定は肥大化しますし、「痒いところに手が届かない」部分もどうしても出てきます。

それが嫌だったので、**プラグインを探して組み合わせるのではなく、欲しい機能を AI に Lua でゼロから書いてもらう**というスタイルで Neovim の設定を育ててきました。今ではプラグインを一才使用せずに自分の理想のエディタが動いています。

本記事では、プラグインと比較したメリット・デメリットや実際に作った機能を紹介します。

# Neovim を使ったことがない方へ

Neovim は他のエディタと違って、UI そのものが Lua のコードでできているので、拡張機能の API で許された範囲だけでなく、見た目や操作感まで含めて自由に作り替えられます。この「土台ごと自分好みにできる」自由度の高さが、AI と組み合わせたときに理想のエディタへ近づけやすい理由です。実際にどんな機能を作ったかもこの後紹介するので、「こんな機能も作れるんだ」と参考にしていただいて、実際に触ってみてもらえたら嬉しいです。

# プラグインを使う場合と比較したメリット・デメリット

## メリット

メリットは大きく 3 つあります。

- **中身が全部読める・直せる**: プラグインだとブラックボックスになりがちな挙動も、自分（と AI）が書いたコードなので、気に入らない部分はその場で直せます。
- **自分好みにできる**: 既製のプラグインでは妥協しがちな細かい挙動も、自分の好みに合わせて自由に調整できます。
- **機能同士を連携させやすい**: 別々の作者が作ったプラグイン同士だと連携が難しいこともありますが、全部自分で書いているので、内部の仕組みを共有したり、機能をまたいで動かしたりしやすいです。

## デメリット

もちろんいい面ばかりではありません。

- **保守も全部自分（と AI）の責任**: プラグインなら誰かが直してくれるバグも、全部自分で気づいて直す必要があります。
- **困ったときに頼れる先が少ない**: 完全に自分専用の実装なので、エラーが出ても検索して解決策が出てきたり、誰かに相談したりがしにくいです。
- **枯れたプラグインほどの完成度にはなりにくい**: 長年使われてきたプラグインが踏んできたエッジケースを、自分で一つずつ踏んで直していくことになります。

当たり前ではありますが、このように自作は自由度が高い分、保守や安定性は自分で引き受けることになります。プラグインの手軽さを取るか、自由度の高さを取るかはトレードオフだと思っていますが、AI がが益々発達するおかげで自作の負担がかなり減った今は、以前よりメリットの方を強く感じるようになりました。既存のプラグインやその他ツールの挙動を参考にできるので、割と簡単に充実したツールも作りやすいです。（素晴らしいプラグインやツールを作ってくださった先人に感謝🙏）

## Git 操作画面

ブランチ切り替え、コミット、ステージング/アンステージ、Stash、Worktree の追加削除、コンフリクトの解消、GitHub の PR や CI ステータス確認まで、Neovim の中だけで完結する Git 操作画面です。`lazygit` の挙動を参考にしながら作っています。

## Docker 操作画面

## Neovim の情報を AI に渡す仕組み

Neovim が内部に持っている情報（LSP の定義・参照・シンボル・ホバー、診断、開いているバッファなど）を、ローカルの HTTP API 経由で AI から読めるようにする機能です。grep と違って LSP はスコープを解決してくれるので、同じ名前のシンボルや import のエイリアスを AI が取り違えることがありません。問い合わせている間もエディタの操作は止まらないようになっています。

## 差分レビューをブラウザで AI と一緒に

作業ツリーの差分をブラウザで開いて、行単位でコメントを付けながら AI とやり取りできる機能です。コメントへの返信や unified / side-by-side 表示の切替もでき、差分自体は保存や git 操作のたびに自動で更新されます。

## コードにメモを残す仕組み

ファイルの特定の行にメモを残せる機能です。ブラウザからも AI からも同じメモを参照・追記できるので、AI がメモを残して人間が読んだり、逆に人間が残したメモを AI が参照したりできます。

# その他の機能

紹介しきれなかった機能も挙げておきます。

## エディタ / UI

- 起動時にファイルを指定しなかった場合に表示する、編集できないスタート画面（`alpha.nvim`や`dashboard-nvim`のような機能）
- 開いているファイルをタブのように並べて切り替えられる表示（`bufferline.nvim`のような機能）
- 各ウィンドウの上部に、開いているファイルのパスを常に表示（`barbecue.nvim`のような機能）
- 各ウィンドウにスクロールバーを表示（`nvim-scrollbar`のような機能）
- ファイラーや Git 画面のような一覧系の画面ではテキストカーソルを消して、カーソル行のハイライトだけで現在位置が分かるようにする表示
- フォーカスが外れているパネルは強調を沈めて、どこを操作しているか分かりやすくする表示
- カーソルがあるコードのブロック範囲を縦線でハイライトする表示（`indent-blankline.nvim`のような機能）
- 括弧やクォートを入力すると自動で対になる方も補完してくれる機能（`nvim-autopairs`のような機能）
- 単語や選択範囲を括弧・クォートで囲んだり、外したりできる機能（`nvim-surround`のような機能）
- 画面外にスクロールした親スコープの行を上部に固定表示する機能（`nvim-treesitter-context`のような機能）
- 全角スペースを灰色背景で可視化する機能
- 開いたファイルの中身からインデント幅を自動検出して適用する機能（`vim-sleuth`のような機能）
- `:q` などで Neovim を終了する直前に確認ポップアップを出す機能（強制終了は確認なし）
- 編集用のウィンドウが無くなり、ファイラーや Git 画面などの補助ウィンドウだけが残った場合に自動で終了する機能

## ファイル / 検索 / ナビゲーション

- ファイル内容やファイル名をあいまい検索し、そのまま置換もできる機能（`telescope.nvim`や`fzf-lua`のような機能）
- パスの断片を入力するとファイルやフォルダ名を補完してくれる機能（`cmp-path`のような機能）
- TODO や FIXME などのコメントタグをプロジェクト全体から検索して一覧表示する機能（`todo-comments.nvim`のような機能）

## Git

- 編集中の行にその行の最終更新者や日時をインラインで表示する機能（`gitsigns.nvim`のような機能）
- 変更のある行をエディタの余白に表示する機能（`gitsigns.nvim`のような機能）
- 現在行や選択範囲の GitHub 上のパーマリンクを生成してコピーする機能（`gitlinker.nvim`のような機能）
- コンフリクトが起きたブロックを色分けして、現在側・入力側・両方などを選んで解消できる機能（`git-conflict.nvim`のような機能）

## LSP

- 各言語のサーバー設定と、ホバー表示・リネーム・コードアクション・フォーマット・診断へのジャンプといった基本機能（`nvim-lspconfig`のような機能）
- カーソル位置の定義元・参照元・型定義・実装をプレビューパネルで確認できる機能（`glance.nvim`のような機能）
- 関数名や変数名（シンボル）をあいまい検索して一覧から移動できる機能（`aerial.nvim`のような機能）
- 入力中に自動でメニューが出る補完機能（`nvim-cmp`や`blink.cmp`のような機能）
- 関数の引数ヒントを自動表示するシグネチャヘルプ（`lsp_signature.nvim`のような機能）
- 開いているファイル全体の診断をまとめて確認できる問題パネル（`trouble.nvim`のような機能）

## ターミナル

- リポジトリのルートですぐに開けるターミナル（`toggleterm.nvim`のような機能）
- ターミナルのバッファをタブや一覧から隠し、キー一つでエディタとの行き来ができるようにする機能（`toggleterm.nvim`のような機能）

## その他

- 編集中の Markdown や HTML をブラウザでプレビューし、保存すると自動で更新される機能（`markdown-preview.nvim`のような機能）
- `.http` / `.rest` ファイルに書いた HTTP リクエストを実行し、結果を確認できる機能（`rest.nvim`のような機能）
- 選択範囲をファイルパス・行番号付きのコードブロックとしてコピーする機能
- バッファの内容を丸ごとコピーする機能
- キーバインドを一覧化してあいまい検索できるチートシート（`which-key.nvim`のような機能）

# さいごに

プラグインを組み合わせて妥協するのではなく、欲しい機能を AI に一つずつ実装してもらう、というスタイルで Neovim を育ててきました。今後も気になる挙動を見つけるたびに、AI と一緒に育てていく予定です。
